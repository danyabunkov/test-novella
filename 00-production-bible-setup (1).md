# Производственная библия: 10 игр на ИИ-конвейере
### Полное руководство от железа до релиза. Движок под каждый проект, контент EN + RU, промпты готовы к копипасту.

> **Как пользоваться этим документом.** Часть 0–2 настраиваешь один раз (железо, конвейер, тулинг). Дальше — 10 проектов, каждый самодостаточен: ты создаёшь репозиторий, копируешь блок проекта в `GAME_DESIGN.md`, скармливаешь финальный промпт Claude Code, генеришь арт по готовым промптам, обучаешь LoRA. В конце — шаблоны `CLAUDE.md`, `AGENTS.md` и большие стартовые промпты.

# ЧАСТЬ 0. Реальность по твоему железу

**RTX 5060 Ti 16GB — рабочая карта для этого пайплайна.** Главное узкое место — не память, а скорость (меньше CUDA-ядер, чем у 5070+). Что это значит на практике:

| Задача | Статус на 5060 Ti 16GB | Заметки |
|---|---|---|
| SDXL txt2img 1024×1024 | Отлично (~6 it/s) | Основная рабочая лошадка |
| SDXL + LoRA (несколько одновременно) | Отлично | Влезает в 16GB |
| Обучение LoRA на SDXL | Хорошо, но ~в 2× дольше топов | 15–30 картинок → ~20–40 мин вместо ~10–20 |
| Flux.1 (fp8) + LoRA | Впритык (15–16GB) | Возможно, но без запаса; держи fp8, не bf16 |
| ControlNet + IP-Adapter + upscaler в одном workflow | Работает | Следи за VRAM, выгружай модели |
| Видео-генерация (AnimateDiff/Wan) | Базово/ограниченно | Не основной сценарий, по желанию |

**Вывод:** строим пайплайн на **SDXL + LoRA + ControlNet + ADetailer** локально в ComfyUI. Flux — опционально для отдельных «парадных» иллюстраций (ключевой арт, обложка Steam), где не жалко времени. Тяжёлую генерацию, если упрёшься в скорость, выноси на облачный GPU поштучно.

# ЧАСТЬ 1. Технический сетап (настраиваешь один раз)

## 1.1. Базовое окружение генерации
1. **ОС/драйверы:** свежий NVIDIA-драйвер + CUDA. Если основная машина — Windows, для ComfyUI это ок; для стабильности обучения LoRA многие держат Ubuntu 24.04 (по желанию, не обязательно).
2. **ComfyUI** — основной интерфейс генерации (нодовый, лучший контроль, весь экосистемный тулинг под него). Альтернатива для быстрых правок — A1111/Forge, но ComfyUI выигрывает в воспроизводимости (workflow = файл).
3. **Модели (checkpoints):** базовый SDXL + 1–2 стилевых файнтюна под нужную эстетику (аниме-стиль, полу-реализм, и т.д. — конкретные под проекты ниже). Качай с Civitai.
4. **Расширения ComfyUI (обязательный минимум):**
   - **ControlNet** (OpenPose, Depth, Canny) — контроль позы и композиции
   - **IP-Adapter** — перенос внешности/стиля по референсу
   - **ADetailer / FaceDetailer** — авто-починка лиц и рук
   - **Ultimate SD Upscale** — апскейл до финального разрешения
   - **WD14 Tagger** — авто-теггинг датасета под обучение LoRA
5. **Обучение LoRA:** **kohya_ss** (GUI поверх sd-scripts) — стандарт. Альтернатива без локального GPU — облачный тренер (Civitai on-site trainer) поштучно.

## 1.2. Папочная структура каждого арт-репозитория (единый стандарт)
```
art/
  _style/              # стилевой бэйз: промпт-префикс, негатив, палитра, сэмплер
    style_base.txt
    negative.txt
  characters/
    <name>/
      dataset/         # 15–30 рефов для обучения LoRA
      lora/            # обученный .safetensors
      sheet.md         # «паспорт» персонажа: внешность, одежда, сид
      outputs/         # финальные спрайты/эмоции
  backgrounds/
  cg/                  # событийные иллюстрации
  ui/                  # купленные/бесплатные UI-ассеты
  workflows/           # .json воркфлоу ComfyUI (воспроизводимость)
```

## 1.3. Дисциплина консистентности (это критично — без неё всё развалится)
- **Один сид + один стилевой префикс на проект.** Записывай сид в `style_base.txt`.
- **LoRA на каждого ключевого персонажа** (15–30 картинок, единая внешность/одежда). Это единственный надёжный способ держать одно лицо во всех сценах.
- **ControlNet OpenPose** для póз спрайтов, **Depth** для согласования фонов.
- **Каждый кадр финалится:** FaceDetailer → инпейнт рук → Ultimate SD Upscale. Сырое не отгружаем.
- **Один воркфлоу-файл на тип ассета** (спрайт / фон / CG) лежит в `workflows/` — чтобы повторять результат через месяцы.

# ЧАСТЬ 2. Тулинг для агентной разработки (Claude Code / ChatGPT)

## 2.1. Какие MCP-серверы реально помогут
Ты уже работаешь с MCP, так что по делу — что подключить под геймдев-конвейер:

| MCP / инструмент | Зачем в этом проекте |
|---|---|
| **Filesystem MCP** | Агент видит структуру репо, читает/пишет файлы игры напрямую |
| **Git / GitHub MCP** | Коммиты, ветки, PR, CI — агент ведёт историю сам |
| **Playwright / Puppeteer MCP** | Прогон веб-сборки (Ren'Py/Godot умеют HTML5) для авто-проверки сцен |
| **Sentry MCP** | Тебе знаком — ловить краши в плейтесте сборок |
| **SQLite/DuckDB MCP** | Хранение и анализ плейтест-метрик, баланса, A/B по хукам |
| **Fetch/Web MCP** | Агент сам тянет доки движка/ассетов |

**Не усложняй:** для каждого репо минимум — Filesystem + Git. Остальное по необходимости.

## 2.2. Локальная агентная гигиена
- **`CLAUDE.md` + `AGENTS.md` в корне каждого репо** (шаблоны в конце документа) — единые правила кода, стиля, структуры.
- **Makefile как единая точка входа** (`make run`, `make build`, `make test`, `make package`) — тебе это уже близко по trading-agent.
- **ADR-first** для нетривиальных решений (как у тебя в Python-проектах) — каждое решение по механике фиксируется как ADR.
- **CI на GitHub Actions** — линт скриптов, сборка, упаковка билда-артефакта.
- **Тесты:** для Ren'Py — проверка, что все ветки достижимы и нет битых меток; для Godot — unit-тесты логики пазлов (GUT-фреймворк).

## 2.3. Где какой ИИ
| Слой | Инструмент |
|---|---|
| Код движка, сборка, рефактор, CI | **Claude Code Max** |
| Сценарий, ветвление, диалоги, лор | **Claude** (длинный контекст) + ChatGPT для альтернатив |
| Концепт-арт, мудборд | **Midjourney** |
| Финальные персонажи/сцены | **SDXL + LoRA** локально |
| Точечные правки кадра | **Nano Banana (Gemini image)** |
| Локализация EN→RU и вычитка | **Claude/ChatGPT** + ручная вычитка (ты носитель RU) |

## 2.4. Бесплатные ассеты, которые реально закроют не-генеримое
Генеришь ты картинки; UI/шрифты/звук дешевле и безопаснее взять готовыми (single art style, лицензия под коммерцию):
- **Kenney (kenney.nl)** — CC0, UI-киты, иконки, звуки, шрифты, без атрибуции. Первый стоп.
- **itch.io → game-assets/free** — фильтр по CC0; UI-паки, транзишены, SFX.
- **CraftPix (free секция)** — GUI/иконки/фоновые элементы под 2D-жанры.
- **game-icons.net** — векторные иконки под UI пазлов/аркад.
- **OpenGameArt** — добивать специфику (проверяй лицензию каждого ассета).
- **Звук/музыка:** Kenney audio + freesound (CC0-фильтр); для музыки — Suno/Udio как ИИ-вариант, либо CC0-библиотеки.

> Правило: **UI и шрифты — готовые CC0; весь «художественный» арт — генерация.** Так ты экономишь время на не-творческом и держишь визуальную подпись на генерации.
