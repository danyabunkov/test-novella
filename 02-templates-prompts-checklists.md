## A. Шаблон `CLAUDE.md` (Ren'Py-проект)

```markdown
# CLAUDE.md — <PROJECT_NAME>

## Что это
Визуальная новелла на Ren'Py. Жанр: <…>. Хук: «<одна строка>».
Контент: английский (исходный) + русская локализация через Ren'Py translate.

## Принципы кода (соблюдать строго)
- Чистый профессиональный код даже в личном проекте.
- Логическое разделение файлов: один label-блок главы = один .rpy.
- Самодокументируемый код, комментарии только «почему», не «что».
- Все строки, видимые игроку, — через систему перевода (translatable).
- Никаких хардкод-путей к ассетам вне `images.rpy` / define-блоков.

## Структура
game/
  script.rpy          # точка входа, флаги, старт
  chapters/           # по файлу на главу
  characters.rpy      # define персонажей
  images.rpy          # объявления спрайтов/фонов/CG
  screens_custom.rpy  # кастомные экраны (если есть механика)
  tl/ru/              # русская локализация
art/                  # см. арт-стандарт (не коммитим dataset/, только финал)

## Definition of Done для сцены
- Все ветки достижимы, нет битых меток (`make lint`).
- Спрайты/фоны объявлены, не падает на missing image.
- EN-текст вычитан; RU-строки присутствуют.
- Сцена проходится от старта до концовки без ошибок.

## Команды (Makefile)
- make lint     # проверка веток и меток
- make run      # запуск
- make build    # сборка дистрибутива
- make tl       # извлечь строки на перевод

## Не делать
- Не генерировать игровой арт (это вне агента; арт делаю я по арт-промптам).
- Не добавлять аналитику/трекеры без явного запроса.
```

## B. Шаблон `CLAUDE.md` (Godot-проект)

```markdown
# CLAUDE.md — <PROJECT_NAME>

## Что это
Игра на Godot 4 (GDScript). Жанр: <puzzle / arcade / hidden-object / cozy>.
Хук: «<одна строка>». Локализация: EN + RU через Godot CSV-translation.

## Принципы кода
- Чистый профессиональный код, строгая типизация GDScript где возможно.
- Один узел/механика = один скрипт; логика отделена от представления.
- Самодокументируемый код; комментарии только «почему».
- Данные уровней — ресурсы/JSON, не хардкод.
- Никаких localStorage-подобных хаков; состояние через resource save.

## Структура
project/
  scenes/        # .tscn
  scripts/       # .gd (логика)
  levels/        # данные уровней (.json/.tres)
  art/           # импортированные финальные ассеты
  ui/            # CC0 UI (Kenney и пр.)
  tests/         # GUT-тесты логики
  i18n/          # translations.csv (EN/RU)

## Definition of Done
- Кор-механика покрыта GUT-тестами.
- Для пазлов: солвер/валидатор подтверждает корректность каждого уровня.
- Нет ошибок в консоли при прохождении.
- EN+RU строки на месте.

## Команды (Makefile поверх godot --headless)
- make test     # GUT
- make run
- make export-win / make export-web
- make validate-levels  # прогон солвера по всем уровням

## Не делать
- Не генерировать художественный арт (делаю я по промптам).
- Не тянуть тяжёлые плагины без обоснования (ADR).
```

## C. Шаблон `AGENTS.md` (общий, кладётся рядом с CLAUDE.md)

```markdown
# AGENTS.md

## Роль агента
Инженер-исполнитель по этому репозиторию. Реализуешь механику и сценарную
структуру по GAME_DESIGN.md. Арт — внешний (промпты отдельно), ты работаешь
с плейсхолдерами и финальными ассетами, которые я кладу в art/.

## Рабочий цикл
1. Прочитать GAME_DESIGN.md и текущее состояние репо.
2. Для нетривиального решения — сначала ADR в docs/adr/.
3. Маленькие атомарные коммиты, осмысленные сообщения.
4. После каждой фичи — прогон make test / make lint.
5. Не расширять скоуп без явного запроса. Спросить, если неоднозначно.

## Плейсхолдеры
Пока нет финального арта — генерировать цветные плейсхолдеры-заглушки
нужных размеров, чтобы сцены собирались и тестировались.

## Качество
- Сначала корректность и читаемость, потом оптимизация.
- Никаких «магических чисел» — конфиги/константы с понятными именами.
```

## D. Большой стартовый промпт для Claude Code (Ren'Py-проект)

> Скопируй в Claude Code в свежем репозитории. Подставь блок проекта из файла `01-ten-games-design.md` в `GAME_DESIGN.md` заранее.

```
Ты — инженер-исполнитель этого репозитория визуальной новеллы на Ren'Py.
Прочитай GAME_DESIGN.md, CLAUDE.md и AGENTS.md в корне. Затем выполни Этап 1.

КОНТЕКСТ ПРОЕКТА
- Это VN <PROJECT_NAME>. Хук: «<…>».
- Исходный язык EN, потом RU через Ren'Py translate.
- Арт я делаю отдельно (генерация). Ты используешь плейсхолдеры тех же
  размеров и имён, что объявлены в images.rpy, чтобы всё собиралось.

ЭТАП 1 — КАРКАС (сделай сейчас)
1. Инициализируй структуру по CLAUDE.md.
2. Создай characters.rpy с define всех персонажей из GAME_DESIGN.md.
3. Создай images.rpy с объявлениями всех нужных спрайтов/фонов/CG как
   плейсхолдеров (генерируй цветные заглушки нужных размеров).
4. Реализуй script.rpy: старт, главное меню, флаги ветвления из дизайна.
5. Разбей сюжет на главы по файлу на главу в chapters/ со СКЕЛЕТОМ сцен
   (метки, переходы, точки выбора) — пока без финального текста, но со
   структурой всех веток и концовок из GAME_DESIGN.md.
6. Если в проекте есть кастомная механика (см. дизайн) — заведи
   screens_custom.rpy и опиши ADR с планом реализации, но саму механику
   реализуешь на Этапе 2 после моего ревью.
7. Настрой Makefile (lint/run/build/tl) и GitHub Actions (lint+build).
8. Напиши make lint, который проверяет достижимость всех меток и
   отсутствие битых переходов.

ПРАВИЛА
- Маленькие атомарные коммиты.
- ADR для каждого нетривиального решения в docs/adr/.
- Не пиши финальные диалоги сам — это отдельный сценарный этап; оставь
  понятные TODO-маркеры с описанием, что в сцене происходит по дизайну.
- В конце Этапа 1 дай мне краткий отчёт: что собрано, как запустить,
  где смотреть структуру веток, что пойдёт на Этап 2.

Начинай с чтения трёх .md файлов и плана на Этап 1.
```

Требования:

- Объём ~<X> слов. Держи заявленную длину сессии.

## G. Промпт-воркфлоу для арта (как гонять через твой стек)

**Шаг 1 — концепт (Midjourney):** прогони `style_base` + описание персонажа/сцены, отбери 1 удачный кадр как «канон внешности».

**Шаг 2 — датасет для LoRA (SDXL/Midjourney):** нагенери 20–30 вариаций канона (разные ракурсы/выражения, одна одежда/лицо), отбери консистентные. Тегни через WD14 Tagger.

**Шаг 3 — обучение LoRA (kohya_ss):** 15–30 картинок, SDXL, ~10–20 эпох. На 5060 Ti — ~20–40 мин. Сохрани `.safetensors` в `art/characters/<name>/lora/`.

**Шаг 4 — продакшн-спрайты (ComfyUI):** базовый SDXL + твоя LoRA + один сид + ControlNet OpenPose (поза) → генерируешь нейтральную позу, затем варианты эмоций тем же сидом. FaceDetailer → инпейнт рук → Ultimate SD Upscale.

**Шаг 5 — фоны:** SDXL + стилевая LoRA проекта, без персонажей, 16:9, апскейл.

**Шаг 6 — точечные правки (Nano Banana):** «убери объект», «смени выражение», «добавь дождь» — там, где перегенерация дороже правки.

**Шаг 7 — финал:** единый прогон апскейла/цветокоррекции для серии, чтобы всё было «одной рукой».

**Универсальный негатив-промпт (держи в `negative.txt`):**
```
lowres, worst quality, bad anatomy, bad hands, missing fingers, extra
fingers, extra limbs, deformed, mutated, disfigured, watermark, signature,
username, text, jpeg artifacts, blurry, inconsistent style, off-model
```

## I. Порядок исполнения портфеля (рекомендация)

1. **Проект 1 (One Tile Left)** — обкатать Godot-конвейер, солвер, публикацию, минимум арта. Самый дешёвый способ пройти весь путь «идея → Steam» один раз.
2. **Проект 6 (Postcards)** — обкатать Ren'Py + стилевую LoRA на маленькой кинетической новелле.
3. **Проекты 2, 4** — добрать Godot-механики (свет, аркада, реклама/ретеншен).
4. **Проект 3, 5** — стилевые LoRA на сцены/предметы, hidden-object.
5. **Проект 7** — первый серьёзный персонаж-LoRA-проект (5–6 персонажей).
6. **Проекты 9, 8** — гибрид-механики + расследование.
7. **Проект 10 (флагман)** — только после того, как LoRA-конвейер на персонажей отлажен на 7/9. Сюда идёт максимум сил и хука.

> Главное правило по итогам анализа рынка: **хук решает, отзывы — это алгоритм, wishlist копится заранее, скоуп режется безжалостно.** Первые игры — платное обучение; отдача компонуется к третьей-четвёртой.
